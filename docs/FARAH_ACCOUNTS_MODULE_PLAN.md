# قسم الحسابات — خطة تطوير نظام محاسبي احترافي
# FARAH Accounts Module — Professional Accounting Roadmap

> هدف الوحدة: محاسبة شاملة لكل حركة مالية داخل منصة فرح — للإدارة ولجميع أنواع الموردين — بمستوى يقترب من مكاتب المحاسبة العالمية (قيد مزدوج، دفاتر، تقارير مالية، تدقيق).

---

## 1. الرؤية | Vision

**العربية:** كل ريال يدخل أو يخرج من النظام (حجز، ذبح، متجر، قاعة، عمولة، سحب، استرداد) يُسجَّل تلقائياً في دفتر محاسبي موحّد مع ربطه بالطرف (عميل، مورد، منصة) والوثيقة المصدر (حجز #، فاتورة #، طلب #).

**English:** Every SAR in/out (bookings, slaughter, marketplace, venues, commission, payouts, refunds) posts automatically to a unified ledger tied to party (customer, vendor, platform) and source document.

## 2. المستخدمون | Users

| الدور | ما يرى |
|--------|---------|
| **مدير المنصة (Admin)** | كل الحسابات، قيود اليومية، ذمم، تقارير مالية، ضريبة/ZATCA مستقبلاً |
| **مورد قاعات / خدمات** | حسابه فقط: إيرادات، عمولات، سحوبات، فواتير صادرة |

| **محاسب داخلي (دور جديد)** | قراءة/تصدير فقط، بدون تعديل قيود |

## 3. المبادئ المحاسبية | Accounting Principles

1. **القيد المزدوج (Double-entry)** — لا حركة بدون مدين ودائن متساويين.
2. **الفترات المحاسبية** — شهر / ربع / سنة، مع إقفال فترة.
3. **شجرة حسابات (Chart of Accounts)** — قابلة للتوسع حسب نوع النشاط.
4. **مراكز تكلفة / أبعاد** — مورد، مدينة، خط عمل (حجوزات / ذبح / متاجر).
5. **أثر لا رجعة فيه للقيود المُقفلة** — التصحيح بقيد عكسي فقط.

### شجرة حسابات مقترحة (مختصرة)

```
1000 الأصول
  1100 نقد / بوابة دفع
  1200 ذمم عملاء
  1300 ذمم موردين (مدفوعات مستحقة)
2000 الالتزامات
  2100 عمولات مستحقة للمنصة
  2200 محافظ موردين (التزام)
3000 حقوق الملكية / إيرادات المنصة
  3100 إيرادات عمولات
  3200 إيرادات خدمات
4000 المصروفات
  4100 استردادات
  4200 رسوم بوابة الدفع
5000 إيرادات المورد (حساب فرعي لكل مورد)
```

## 4. مصادر القيود التلقائية | Auto-posting Sources

| الحدث في النظام | قيد محاسبي مقترح |
|-----------------|------------------|
| دفع حجز (كامل/عربون) | مدين: نقد / بوابة — دائن: إيراد مؤجل أو ذمم |
| إكمال حجز + عمولة | دائن: إيراد مورد — مدين: عمولة مستحقة للمنصة |
| طلب متجر مدفوع | مدين: نقد — دائن: محفظة مورد |
| سحب مورد | مدين: محفظة مورد — دائن: بنك |
| استرداد | قيد عكسي مرتبط بمرجع الدفع الأصلي |
| فاتورة ذبح / قاعة | ربط برقم فاتورة + PDF |

## 5. واجهات لوحة التحكم | Admin UI (مقترح)

### مسار: `/admin/accounts` — قسم الحسابات

| صفحة | الوظيفة |

- كشف حساب مبسط (مثل كشف بنك)
- تحميل PDF/Excel
- لا يرى قيود موردين آخرين

## 7. نموذج بيانات مقترح | Data Model (Prisma)

```prisma
model ChartAccount { id, code, name, nameAr, type, parentId, isActive }
model JournalEntry { id, date, reference, description, sourceType, sourceId, periodId, createdById }
model JournalLine { id, entryId, accountId, debit, credit, vendorId?, customerId?, dimension? }
model AccountingPeriod { id, year, month, status: OPEN|CLOSED, closedAt }
model VendorLedgerSnapshot { vendorId, periodId, opening, debit, credit, closing }
```

**ربط مع الموجود:** `Payment`, `Booking`, `VendorWallet`, `SlaughterOrder` → حقل `journalEntryId` اختياري.
